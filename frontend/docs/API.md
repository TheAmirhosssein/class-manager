# قرارداد پیشنهادی API — نسخه ۱

Base URL پیش‌فرض: `/api/v1`. همه درخواست‌ها و پاسخ‌ها JSON و UTF-8 هستند. شناسه‌ها string هستند. پاسخ موفق GET فهرست، **آرایه خام** است. پاسخ تک‌موردی object خام است. status موفق ۲۰۰ یا ۲۰۱؛ حذف و خروج می‌تواند ۲۰۴ باشد.

## مسیرها

| متد | مسیر | دسترسی | پاسخ |
| --- | --- | --- | --- |
| GET | `/courses` | عمومی | Course[] |
| GET | `/school` | عمومی، فقط نام عمومی | `{name}` |
| GET | `/classes` | عمومی، فقط متادیتای مجاز | Class[] |
| GET | `/schedule` | عمومی، فقط زمان‌بندی مجاز | Schedule[] |
| POST | `/auth/register` | عمومی، با محدودیت نرخ | `{user}` یا `{message}` برای تأیید ایمیل |
| POST | `/auth/login` | عمومی، با محدودیت نرخ | `{user}` و Set-Cookie نشست |
| GET | `/auth/session` | نشست معتبر | `{user}`؛ بدون نشست ۴۰۱ |
| POST | `/auth/logout` | نشست معتبر | ۲۰۴ یا `{message}`، ابطال کوکی |
| GET | `/classes/:id/students` | مدرس همان کلاس / مدیر | Student[] |
| GET | `/attendance?classId=c10&date=2026-11-06` | مدرس همان کلاس / مدیر | Attendance |
| PUT | `/attendance` | مدرس همان کلاس / مدیر | Attendance ذخیره‌شده |
| GET | `/discipline` | مدرس / مدیر، محدود به حوزه مجاز | Discipline[]، جدیدتر ابتدا |
| POST | `/discipline` | مدرس همان کلاس / مدیر | Discipline ایجادشده |
| POST | `/schedule` | مدرس / مدیر | Schedule ایجادشده |
| DELETE | `/schedule/:id` | مالک جلسه / مدیر | ۲۰۴ |
| PATCH | `/school` | نقش مجاز مدرسه | `{name}` به‌روز‌شده |

این قالب برای سایت یک مدرس طراحی شده است. در محصول چندمدرسه‌ای، لیست‌های عمومی باید به مدرس/مدرسه انتخاب‌شده scope شوند. آمار نمای کلی حاصل متادیتای همین فهرست‌هاست؛ آمار ادعایی بازاریابی در آن نیست. studentCount فقط عدد تجمعی است؛ سرور در صورت خصوصی بودن آن، قرارداد endpoint عمومی را بازطراحی کند.

## مدل‌ها و نمونه پاسخ‌ها

### Course

```json
[{"id":"math10","grade":"10","title":"ریاضی دهم؛ از پایه تا تسلط","subject":"ریاضی ۱","description":"آموزش مفهومی و قدم‌به‌قدم","lessons":24,"duration":"۱۸ ساعت","type":"آموزش + تمرین","topics":["مجموعه‌ها","مثلثات","تابع"]}]
```

grade یکی از رشته‌های `10`, `11`, `12`. topics آرایه string است. دوره و کلاس دو مدل جدا هستند؛ این نسخه پرداخت و enrollment ندارد.

### Class / Student / School

```json
[{"id":"c10","title":"ریاضی دهم — الف","grade":"10","room":"کلاس ۱۰۱","studentCount":6}]
```

```json
[{"id":"s1","name":"آراد احمدی"}]
```

```json
{"name":"مدرسه نمونه"}
```

PATCH مدرسه همین object نام را دریافت می‌کند. طول trimشده نام ۲ تا ۸۰ کاراکتر.

### Schedule

```json
{"id":"t1","classId":"c10","day":0,"start":"08:00","end":"09:30","topic":"مجموعه‌ها و الگوها"}
```

POST همین object بدون id را می‌گیرد؛ id را سرور تولید می‌کند. day عدد صحیح ۰ تا ۶ (شنبه تا جمعه). start/end ساعت ۲۴ساعته HH:mm در منطقه زمانی مدرسه (نمونه Asia/Tehran). بازه باید داخل همان روز، start < end، موضوع ۱ تا ۱۰۰ حرف و بدون تداخل با زمان‌های مدرس باشد. روز تعطیل حذف‌شده فرض نمی‌شود؛ برای تعطیلی یا تاریخ استثنا نیاز به توسعه قرارداد وجود دارد.

### Attendance

```json
{"classId":"c10","date":"2026-11-06","records":[{"studentId":"s1","status":"present"},{"studentId":"s2","status":"absent"}]}
```

GET جلسه ثبت‌نشده object با records خالی برگرداند. PUT همین ساختار با فهرست **تمام دانش‌آموزان کلاس** ارسال می‌کند. وضعیت مجاز: present / absent / late / excused. روی (classId,date) قید یکتا بگذارید. تاریخ ISO `YYYY-MM-DD` است، timestamp نیست. همه studentIdها باید عضو کلاس باشند. وضعیت‌های ناقص، تکراری و شناسه‌های نامعتبر رد شوند.

### Discipline

```json
{"id":"d1","classId":"c10","studentId":"s1","studentName":"آراد احمدی","type":"positive","date":"2026-11-06","note":"مشارکت خوب در تمرین گروهی"}
```

POST بدون id. type یکی از positive / attention. متن trimشده ۳ تا ۱۰۰۰ حرف. سرور studentName معتبر را از رابطه دانش‌آموز تولید کند. GET فقط یادداشت‌های حوزه دسترسی مدرس را برگرداند.

### Auth

درخواست login:

```json
{"email":"teacher@example.com","password":"your-password"}
```

درخواست register: فیلدهای email، password و name. در فرانت طول رمز جدید حداقل ۸ است؛ سیاست نهایی رمز با سرور. ثبت‌نام عمومی فقط کاربر عادی ایجاد کند.

پاسخ login / session / register در صورت فعال بودن نشست:

```json
{"user":{"id":"u1","name":"نام مدرس","role":"teacher"}}
```

role پنل: teacher یا admin. نقش student پنل مدرس را نمی‌بیند. پنل دانش‌آموز در محدوده این تحویل نیست. اگر ثبت‌نام نیازمند تأیید ایمیل است، `{ "message": "برای تأیید حساب ایمیل خود را بررسی کنید." }` بدون user برگردانید. فرانت همان پیام را نشان می‌دهد.

از کوکی Secure/HttpOnly/SameSite مناسب استفاده کنید. endpoint اولیه GET یا سازوکار بک‌اند باید کوکی CSRF غیر HttpOnly با نام `csrftoken` را برای فرانت آماده کند؛ درخواست‌های نوشتنی مقدار آن را در `X-CSRFToken` می‌فرستند. نام‌ها در config قابل تغییرند. اطلاعات محرمانه و کلید سرور در config قرار نگیرد.

## خطاها

```json
{"message":"ساعت انتخاب‌شده با کلاس دیگری تداخل دارد."}
```

کدهای مناسب: ۴۰۰/۴۲۲ اعتبارسنجی، ۴۰۱ نشست نامعتبر، ۴۰۳ منع دسترسی، ۴۰۴ مورد ناموجود، ۴۰۹ تداخل، ۴۲۹ محدودیت نرخ و ۵۰۰ خطای داخلی با پیام عمومی. `message` متن ساده قابل نمایش است. جزئیات SQL، stack trace یا داده محرمانه در آن نباشد. همه ورودی‌ها در بک‌اند اعتبارسنجی شوند. اعتبارسنجی مرورگر صرفاً برای تجربه کاربری است.
