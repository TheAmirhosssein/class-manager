# راهنمای تحویل به توسعه‌دهنده بک‌اند

## مسیر صفحات

همه مسیرها داخل `index.html` با hash اجرا می‌شوند؛ روی هاست استاتیک نیازی به rewrite نیست.

| مسیر | محتوا |
| --- | --- |
| `#home` | صفحه اصلی |
| `#courses` | فهرست و فیلتر کلاس‌ها |
| `#about` | مسیر یادگیری |
| `#schedule` | برنامه عمومی |
| `#panel` | نمای کلی مدرس |
| `#panel/classes` | فهرست کلاس‌ها |
| `#panel/attendance` | حضور و غیاب |
| `#panel/discipline` | یادداشت انضباطی |
| `#panel/schedule` | مدیریت برنامه هفتگی |
| `#panel/settings` | نام مدرسه |

## مراحل ادغام

1. کل پوشه را روی هاست یا پوشه public فریم‌ورک خود قرار دهید؛ مسیر نسبی فایل‌ها حفظ شود.
2. قرارداد API.md را با مدل‌های بک‌اند نگاشت کنید. پاسخ لیست‌ها آرایه خام است، بدون envelope مانند data/results. اگر API فعلی ساختار دیگری دارد، تنها `assets/api.js` را تبدیل کنید.
3. ورود و ثبت‌نام، بازیابی نشست و خروج را با کوکی پیاده کنید. ثبت‌نام عمومی نباید نقش مدرس یا مدیر بدهد.
4. کلاس‌ها، مدرسه، برنامه هفتگی و دوره‌های واقعی را وارد کنید.
5. در config مقدار `demo:false` و مسیر API را تعیین کنید. در استقرار cross-origin مقدار credentials به include تغییر می‌کند و CORS باید origin دقیق و credentials را مجاز کند. راه‌اندازی هم‌مبدأ ساده‌تر است.
6. نام «ریاضی‌نو»، متن‌ها و عنوان صفحه را بر اساس هویت مدرس تغییر دهید. متن‌های معرفی محتوای پیشنهادی‌اند. عنوان کارت‌ها و سرفصل‌ها از API می‌آیند.
7. نشست مدرس، نشست دانش‌آموز، خروج، نشست منقضی، دسترسی ممنوع، لیست خالی و خطای شبکه را در محیط staging بررسی کنید.

## قراردادهای رفتاری

- دسترسی پنل برای teacher/admin در فرانت بررسی می‌شود؛ این بررسی فقط برای UI است. مجوزها و مالکیت مدرسه/کلاس باید در تک‌تک درخواست‌های سرور کنترل شوند.
- فهرست دانش‌آموزان، حضور و غیاب و انضباط نباید عمومی باشند. برنامه نمایش‌داده‌شده در خانه باید فقط اطلاعات مجاز برای عموم داشته باشد.
- نام دانش‌آموز در ثبت یادداشت برای نمایش نمونه ارسال می‌شود. سرور باید نام معتبر را از studentId استخراج کند؛ به studentName ورودی اعتماد نکند.
- تاریخ حضور و یادداشت با ورودی استاندارد date و قالب میلادی ISO ذخیره می‌شود. تاریخ توضیحی در UI با تقویم فارسی نمایش داده می‌شود. ساعات برنامه محلی، بدون offset و با منطقه زمانی مدرسه هستند؛ برای این نمونه Asia/Tehran در نظر گرفته شده است. روز ۰ شنبه و روز ۶ جمعه است.
- تداخل هر دو جلسه این مدرس در یک روز مسدود می‌شود؛ مرز برابر پایان و شروع مجاز است. این بررسی باید در تراکنش سرور نیز تکرار شود.
- `PUT /attendance` وضعیت کامل یک کلاس در یک تاریخ را به صورت idempotent جایگزین می‌کند. وضعیت انتخاب‌نشده مجاز نیست.
- نشست در حافظه UI نگه داشته می‌شود؛ توکن در localStorage ذخیره نمی‌شود. API مرجع نهایی هویت است.
- درخواست‌ها پس از ۱۵ ثانیه timeout می‌شوند. خطای سرور باید message قابل نمایش و بدون جزئیات حساس بدهد.

## برداشت از تصویر تخته

موارد خوانای تصویر: ورود، نام مدرسه، کلاس‌ها، حضور و غیاب، انضباط و برنامه کلاسی. جزئیات ناخوانا به صورت الزام قطعی در نظر گرفته نشده‌اند. تصویر دوم مرجع رنگ سبز بوده است. هویت واقعی مدرس یا مدرسه ارائه نشده، بنابراین نام‌ها نمونه‌اند.
